# マネジメントゲーム（製造業・ジュニアルール）

製造業の会社を経営して決算を競うマネジメントゲームを、ゼミ用にブラウザで遊べるようにしたものです。

**遊ぶ：https://osu-denken.net/mg-game/** （スマホ・PCのブラウザで開くだけ。インストール不要）

大阪産業大学 電子計算研究部（電研）の作品として公開しています。

## 遊び方

| モード | 内容 |
|---|---|
| CPUと対戦 | 自分1社＋CPU 1〜5社。CPUの性格は「堅実・積極・バランス」から選べる（おまかせも可） |
| 1台を回して対戦 | 1台のPC・タブレットを順番に操作。入札価格は目隠し画面を挟んで1人ずつ入力 |
| オンライン | ホストが「部屋を作る」→ 4文字の部屋コードを共有 → 参加者は「部屋に参加」。空いた枠はCPUで埋められる |

- 期数（1〜5期）と、1期あたりの手番数（1人6〜20回）を開始前に選べます。
- 現金出納帳・原価計算・STRAC・損益・B/S・順位表は自動で作られます（「決算書」ボタン）。
- ゲームはその端末のブラウザに自動保存され、タイトルの「続きから」で再開できます。
- はじめての人はタイトルの「遊び方」を見てください。
- 一度開いたあとはオフラインでも CPU 対戦と「1台を回して対戦」が遊べます（オンライン対戦はインターネットが必要）。

### 商品販売（入札）の流れ

1. 親（販売する人）がマーケットと個数を宣言する
2. ほかの会社が「参加するか・何個出すか」を決める（全員に公開）
3. 参加者全員が入札価格を隠して決める（参加者がいないマーケットは、親が上限価格で売れる）
4. 競争価格（入札価格 −2（親）−2×青チップ）の安い順に、マーケットの空きの数まで売れる

## 自分のPCで起動

上のURLで遊べますが、手元で動かす場合はファイルを置いたフォルダで静的サーバーを立てて開きます。

```bash
python -m http.server 8765
```

ブラウザで http://localhost:8765 を開きます。CPU対戦と「1台を回して対戦」は `index.html` を直接開いても遊べます。

オンライン対戦は、全員が上のURLを開いて、ホストが作った部屋コードで参加します。

## オンライン対戦の仕組み

- 通信は PeerJS（WebRTC）で、ブラウザ同士を直接つなぎます。PeerJS は `js/vendor/` に同梱しています（MITライセンス）。最初に相手を見つけるときと、直接つながらないときの中継には、PeerJS が無料で公開しているサーバーを使います。サーバーの用意や設定はいりません。
- ホストの端末がゲームを進め、参加者は操作を送って結果を受け取ります。ホストのタブを閉じるとゲームが止まります（ホストが「続きから」で同じ部屋コードを開き直せば、参加者は再接続できます）。
- 参加者の通信が切れると、ホストの画面に表示されます。戻れない参加者がいるときは、その場で「CPUに交代」できます。参加者が同じ部屋コードで入り直すと、自動で参加者に戻ります。
- 参加者の端末を見分けるIDはホストにだけ送られ、ほかの参加者には見えません（他人の会社を操作できないようにするため）。入札価格も結果が出るまでほかの人には送られません。
- 学内Wi-Fiなどでつながらない場合は、スマホのテザリングなど別の回線で試してください。

## ルールの調整

`js/data.js` に数値がまとまっています。画面・CPU・ルール表もここを参照します。

- マーケット（材料単価・上限価格・マーケットボリューム）、各単価、期末費用単価表、借入条件、税率
- `RULE`：生産能力・販売能力・マーチャンダイザーの値引き・親や青チップの価格競争力など
- `RISK_RATIO`：意思決定カードのうち「リスクカードを引く」の割合（標準 0.2 ＝ 5枚に1枚）
- `RISK_CARDS`：リスクカード。`weight` が枚数、効果は `js/engine.js` の `applyRisk()` にあります。
  - ゼミのカード：ワーカー退職・セールスマン退職（各退職費5、一般管理費）、倉庫火災発生（材料すべて焼失、保険で1個8）、社長が倒れた（1回休み）、逆回り、窃盗（製品すべて盗難）、工場の機械が壊れる（機械すべて廃棄、帳簿価額を特別損失に）
  - こちらで作ったカード：製造ミス、材料の特別購入、独占販売、研究開発の成功・失敗、広告が大ヒット、クレーム発生
- `RETIRE_FEE`：退職費（標準 5）

## デジタル版で決めたこと（ルール表に書かれていない部分）

- マーケットの材料は毎期首にマーケットボリュームまで補充。材料を買うと空きができ、空きの数まで製品を売れる。
- 期首・期末の支払いで現金が足りないときは自動で緊急借入（10単位）。
- 入札は「参加と個数（公開）→ 入札価格（非公開）」の順。子は1人あたり親が出した個数まで参加でき、競争価格の安い順に、マーケットの空きの数まで上位から売れる（例：空き6で4人が2個ずつなら1〜3位が売れる）。参加者がいないマーケットは親が上限価格で売れる。
- 親と参加した子の全員の競争価格が同じなら親の負け（順位は最後）。子が2人以上いて空きに全員分が入らないときは、子だけで価格を出し直す（個数は最初のまま・辞退も可）。
- 一部だけ同じ競争価格のときは、青チップの多い順、親の順。再入札でも同じならジャンケンの代わりにランダムで決定。
- リスクカードはクリックするまで表示し、その間CPUは止まる。
- 平均単価は四捨五入、売上原価などは差額で求める（シートと同じ手順）。
- 法人税等は50%。前期繰越利益剰余金がマイナスなら通算後に計算し、翌期首に納付。

## テスト

エンジン（ルール・会計・入札）とCPUのテストがあります。Node.js 18 以上で次を実行します（追加のインストールは不要）。

```bash
npm test        # または node --test
```

js/app.js              画面遷移・入力・保存

tests/                 エンジンとCPUのテスト
